## The six read methods in comparison

All arms are **one architecture family**: an identical WRITE path (independent
per-segment inner-loop writes into `S=4` segments × `M=2` memory tokens on the
same 8-pair contexts), an identical READ row (`[memory chips?] → query →
answer` under one causal attention), and a single swappable **memory-access
module** below. The arms differ only in that module's **read schedule** — the
badge in each panel's top-right corner: *one pre-pass read* (a), *no read*
(b), or *per-token × per-layer taps* (c, d), restricted to `M` learnable chips
and made query-aware by a conditioning pass (d′) — or not (d″). The one-shot
control and the linear-state arms are deliberately drawn as siblings: the same
channel the reader consumes, filled once up-front vs continuously in-pass.

**(a) Hopfield one-shot — the same channel, read ONCE before the pass (EM 0.25).**
One compressed query scores every segment once; the mixture becomes a static
prefix chip that every answer position consumes.

![Hopfield one-shot](figures/read_a_hopfield.svg)

**(b) Bank-prefix control — the chips ARE the raw bank (EM 0.02).** No
memory-access module at all: all stored tokens ride in the context; retrieval
must emerge from the frozen reader's attention.

![Bank-prefix control](figures/read_b_bank_prefix.svg)

**(c) Exact-softmax heads — re-read at every token × layer, normalized (EM 1.00).**
The bank stays unfolded; each tap is normalized attention over N separate
items, so the payload is never mixed into one slot.

![Exact-softmax heads](figures/read_c_exact_softmax.svg)

**(d) Linear-state read — the same taps off a folded state (EM 0.995–0.998).**
The bank is folded once into per-head states `S_r = Σ k vᵀ`; every position
and layer taps the superposed state with unnormalized weights.

![Linear-state all positions](figures/read_d_linear_all.svg)

**(d′) Interface tokens — the same taps restricted to M chips, conditioned by pass 1 (EM 0.999).**
Only `M` learnable chips read the state; pass 1 lets the query condition them
before the answering pass fills them per layer.

![Interface two-pass conditioned](figures/read_dprime_interface_cond.svg)

**(d″) Interface tokens, query-blind — the same restricted taps, pass 1 removed (EM 0.01).**
`read_state_interface_conditioning=false`: the chips are the raw learnable
`M_0`; sitting left of the query and causal, they can never see it — the
"left-prefix causal" configuration the spec's causality trap warned about,
run deliberately as the ablation's third cell.

![Interface query-blind](figures/read_dprime2_interface_nocond.svg)

![EM curves](figures/em_curves.svg)

## Setup

- **Model:** tiny Llama-architecture model **trained from scratch** (Llama-3.2
  config class overridden to 4 layers / 4 heads / `d=128`), outer loop
  `grad_mode="second"`, `K=2` inner steps, frozen nothing (all params train).
- **Task:** ordered two-key concat `?!K1:?!K2:` → `V1!V2!|` over 8 stored KV
  pairs in 4 pair-aligned segments — cross-segment pairs are the probe
  population (15/16 of eval). The concat eval is all two-key, so
  `eval_exact_match` and `eval/two_key_both_values_exact_match` coincide.
- **Read config:** `read_state_heads=4`, all layers instrumented,
  `beta_init=1.0`, `gate_init=0.1`.
- **Seeds:** 4378 / 43894 / 2343 for every arm.

## Main results (best two-key both-values EM per seed)

| arm | seed 4378 | seed 43894 | seed 2343 | mean | first ≥ 0.99 | stopped at |
|---|---|---|---|---|---|---|
| (a) hopfield one-shot | 0.2396 | 0.2488 | 0.2556 | **0.248** | never | 81–107k |
| (b) bank-prefix control | 0.0256 | 0.0244 | 0.0230 | **0.024** | never | 83–97k |
| (c) exact-softmax heads | 1.0000 | 1.0000 | 1.0000 | **1.000** | 19.5–29k | 47–76k (at 1.0) |
| (d) linear-state all | 0.9980 | 0.9950 | 0.9980 | **0.997** | 33k / 84k / 34.5k | 90–117k |
| (d′) interface, conditioned | 0.9988 | 0.9998 | 0.9986 | **0.999** | 30.5–31.5k | 92–117k |
| (d″) interface, query-blind | 0.0026 | 0.0202 | 0.0126 | **0.012** | never | ~100k |

**Every per-token/per-level read solves ordered-concat; both one-shot-style
interfaces fail.** The failure decompositions match the spec's analysis:

- **(a)** gets each value individually ≈ 0.5 (`v1` 0.495–0.504, `v2` 0.479–0.504)
  and both together ≈ 0.25 ≈ 0.5 × 0.5 — the single compromise query picks the
  right segment about half the time; the convex mixture then makes joint
  retrieval multiplicative.
- **(b)** is worse than (a) everywhere (`v1`/`v2` ≈ 0.14–0.16, both-single
  ≈ 0.002): with the SAME stored tokens that (c)/(d)/(d′) turn into 1.00, the
  frozen reader cannot do the retrieval by attention. Its failure indicts the
  **prefix interface**, not write quality — the 2026-10-20 re-reading of the
  decision tree is confirmed.

## The conditioning ablation — pre-registered prediction: **HOLDS**

Prediction (STATUS.md 2026-10-20 (b), recorded before any result existed):
*"the query-blind arm underperforms the conditioned interface arm on BOTH the
two-key concat exact-match and single-key exact-match, because retrieval
degrades to query-agnostic compression through the fixed M·d channel."*

| seed | (d′) conditioned | (d″) query-blind | Δ |
|---|---|---|---|
| 4378 | 0.9988 | 0.0026 | 0.996 |
| 43894 | 0.9998 | 0.0202 | 0.980 |
| 2343 | 0.9986 | 0.0126 | 0.986 |

- **Two-key EM:** holds with a >0.98 gap on every seed. Per-value EM inside
  the joint answer tells the mechanism: conditioned `v1`/`v2` ≈ 1.0 each;
  query-blind `v1`/`v2` ≈ 0.04–0.14 — neither interface token reliably
  retrieves anything in particular, and the joint answer ≈ v1·v2 ≈ 0.01.
- **Single-key EM:** the ablation manifest (by design) has no single-key-data
  arm, so the direct clause is untested; the two available single-key-flavoured
  views both collapse for the blind arm: the probe-format forgetting matrices
  (see below) and `two_key_both_single_exact_match` (conditioned 0.013–0.279 →
  blind 0.0004–0.0012).
- **Either outcome was informative — this outcome justifies the two-pass
  machinery:** conditioning is load-bearing. Removing pass 1 halves the
  interface arm's read compute and destroys the function.

**The blind arm fails for the *predicted* reason, not mechanically.** Final
diagnostics are healthy and near-identical between the pair:

| diagnostic (final) | (d′) conditioned | (d″) query-blind |
|---|---|---|
| `read_state_gate_abs_mean` | 0.222–0.239 | 0.183–0.247 |
| `read_state_mu_over_x_norm_ratio` | 0.023–0.033 | 0.019–0.065 |
| `read_state_beta_mean` | 1.60–1.69 | 1.45–1.82 |
| `read_state_cross_talk` | 0.132–0.137 | 0.117–0.141 |
| eval loss (min) | 0.0003–0.0011 | 0.67–1.18 |

Gates did not collapse; the blind arm reads the state as strongly as the
conditioned one and sharpens β the same way — but what flows through the fixed
`M·d` channel cannot depend on the query, so nothing at the interface
positions can route by key. This is the **causality trap demonstrated
empirically**: the read works, the information pathway cannot.

## Ladder decision criteria (spec § Experimental plan) — outcomes

1. **(b) vs (a):** both fail. With (c)/(d)/(d′) solving concat on the SAME
   stored tokens, (b)'s failure indicts the prefix interface (frozen reader +
   raw-token prefix at training scale), not write quality. H2 survives in its
   meaningful form: the read interface is the bottleneck.
2. **(d) vs (b):** the folded O(1) state solves what the O(N) prefix cannot —
   at this scale the superposed-state read is not a lossy approximation of
   "just look at the bank"; it is the working mechanism.
3. **Regression guard (single-key):** the dedicated single-key arm (linear-state
   config on `N8-K2V2-V62_1M`) reaches **EM 0.997 / 0.9986 / 0.9978** — the
   state read retains the task the Hopfield mode already solved.
4. **(c) vs (d):** exact per-token attention converges ~1.5× faster (first
   ≥0.99 at 19.5–29k vs 33–84k) and lands at exactly 1.00 vs 0.995–0.998. The
   superposition costs sample efficiency, not (at N = 8 bank items) final
   accuracy. The interference-vs-N curve (missing experiment #5) decides
   whether this stays true at scale.
5. **(d′) vs (d):** per-token reads are NOT needed — M·L query-conditioned
   interface reads match all-position reads in final quality (0.999 vs 0.997)
   and are the most seed-consistent solver (30.5–31.5k to 0.99 on all seeds).
   The cheaper interface architecture is sufficient **given pass 1**.
6. **(d′) vs (d″):** conditioning is the load-bearing part of the interface
   arm. A practical corollary: any future cheap variant must keep a
   query→interface pathway (two-pass, or a masked single-pass layout); a bare
   left prefix is worthless.

## Forgetting matrices (read with a format caveat)

The per-segment probes are single-key `?!K:V!|` queries
(`build_kv_probe_queries`), which the concat-trained arms never see in
training — for these arms the matrices measure **single-key-format transfer**,
not forgetting. Mean diagonal (EM right after the pair's own segment) and
last-column (after all 4 segments) over 3 seeds:

| arm | diag | last col | note |
|---|---|---|---|
| bank_prefix_control | 0.215 | 0.124 | |
| linear_all | 0.029 | 0.028 | |
| linear_exact_softmax | 0.559 | 0.430 | seed spread 0.34–1.00 diag |
| linear_interface | 0.040 | 0.034 | |
| linear_interface_nocond | 0.107 | 0.046 | |

No arm shows a within-training degradation pattern (last col ≤ diag
everywhere); the spread across seeds of the SAME arm (exact-softmax 0.34 vs
1.00) marks this as format-transfer variance, not memory loss. The clean
single-key result remains the dedicated regression arm (0.997+ EM). A
concat-format forgetting probe (two-key queries restricted to earlier
segments) is the honest instrument going forward.

## Conclusions

1. The H3 read design (per-token, per-level linear-attention reads) **fixes
   ordered-concat** — the failure that motivated it — with no degradation on
   single-key retrieval.
2. Where the loss comes from is now mapped: compression+convexity kill the
   one-shot read (a), the raw prefix kills the frozen-reader route (b), and
   **query-blindness kills an otherwise-healthy state read** (d″). The common
   requirement is per-level reads whose queries can see the task query.
3. The deployable configuration is (d′): interface-only reads (read cost ≈ the
   old one-shot) + the two-pass conditioning. Pass 1 is not optional overhead;
   it is the pathway that makes the interface query-aware.
4. Open next steps (PROGRESS.md): interference curve vs N (does (d) close on
   (c) at larger banks?), pointer chasing (depth-bounded iteration is the
   remaining claim), writer×read factorial, babilong sanity.
